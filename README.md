# NOIR ARCHIVE — React + Node.js + Microsoft SQL Server

Демонстрационный full-stack fashion store в чёрно-белой эстетике. **SSMS 22 — инструмент управления SQL Server, а не сам сервер.** Нужен запущенный **SQL Server 2019/2022/2025 или SQL Server Express** с включённым TCP/IP и SQL Server Authentication.

## Что внутри

- React + Vite: анимированная главная, каталог из базы, поиск, категории, сортировка, страницы товаров, тема, регистрация, авторизация, корзина, оформление без оплаты, кабинет и PDF с деталями заказа, отправка отзывов, форма обращений, Ring Size Finder с калибровкой и страницы ошибок.
- Express API + Prisma с `provider = "sqlserver"`: пользователи, сессии HttpOnly, товары, остатки, заказы, отзывы и обращения; админские API защищены на сервере.
- `/admin`: обзор, редактирование и архивирование товаров, управление статусами заказов, модерация отзывов, обращения, список пользователей.
- Seed: 32 примерных товара и опциональный администратор. Демоданные не являются подтверждёнными предложениями брендов.

## 1. SQL Server / SSMS 22 (Windows)

1. Установите **SQL Server Database Engine** (например, Express) и SSMS 22; если SQL Server уже работает, повторная установка не нужна.
2. В SQL Server Configuration Manager включите TCP/IP для экземпляра; для TCP/IP установите фиксированный порт `1433` в IPAll (уберите динамические порты), перезапустите службу SQL Server. Для именованного экземпляра `SQLEXPRESS` проверьте параметры конкретного экземпляра.
3. В свойствах сервера SSMS: Security → **SQL Server and Windows Authentication mode**; перезапустите службу, если меняли режим.
4. Создайте отдельный SQL login (предпочтительно) или настройте `sa` с сильным паролем. Не сохраняйте пароль в репозитории.
5. Откройте SSMS, подключитесь к Database Engine и выполните:

```sql
IF DB_ID(N'noir_archive') IS NULL CREATE DATABASE noir_archive;
GO
```

6. Скопируйте `backend/.env.example` → `backend/.env`. Настройте `DATABASE_URL` для своего SQL Server.

**Пример для localhost:1433 (SQL auth):**

```env
DATABASE_URL="sqlserver://localhost:1433;database=noir_archive;user=sa;password=ВАШ_ПАРОЛЬ;encrypt=true;trustServerCertificate=true"
```

> `trustServerCertificate=true` подходит только для локальной разработки. В production нужен доверенный сертификат и безопасная конфигурация TLS. Если пароль содержит `;`, `=` или другие служебные символы, используйте другой пароль/корректное экранирование Prisma connection string. В зависимости от настройки вашего SQL Server может потребоваться иной порт.

## 2. Установка и запуск из VS Code (Windows PowerShell)

**Требуется Node.js 20+ и npm.** Откройте папку проекта в VS Code и запустите два терминала.

Терминал 1:

```powershell
cd backend
Copy-Item .env.example .env
# Отредактируйте backend/.env, укажите пароль SQL Server и желаемые ADMIN_EMAIL / ADMIN_PASSWORD
npm install
npx prisma generate
npm run db:push
npm run db:seed
npm run dev
```

Терминал 2:

```powershell
cd frontend
npm install
npm run dev
```

Откройте **http://localhost:5173**. API: **http://localhost:3001/api/health**. Админ-панель: **http://localhost:5173/admin**.

### Администратор

Перед `npm run db:seed` задайте в `backend/.env`:

```env
ADMIN_EMAIL=owner@example.com
ADMIN_PASSWORD=UseAVeryStrongUniquePassword123!
```

После запуска войдите этими реквизитами на `/login`. Скрипт создаёт администратора, только если переменные явно заданы. **Если администратор уже существует, seed меняет роль, но не обновляет пароль.** Настоящие пароли никогда не публикуйте.

## 3. Email (SMTP)

В `backend/.env` задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. Когда SMTP отсутствует или письмо не удалось отправить, заказ **всё равно сохраняется**, а интерфейс честно сообщает, что письмо не отправлено. Администратор может повторить отправку в `/admin` → «Заказы». Для production стоит добавить очередь и мониторинг повторных доставок.

## 4. Оплата и чеки

Онлайн-оплата **не подключена**, реальные деньги не списываются. Все заказы получают статус `UNPAID`. Менять его в панели следует только после внешнего подтверждения платежа. Для Kaspi Pay/эквайринга нужны договор, API-ключи, безопасная серверная интеграция и проверенные webhook. Скачиваемый PDF — **подтверждение заказа, НЕ официальный фискальный чек**. Фискализация требует законной интеграции с фискальным провайдером.

## 5. Что ещё нужно для production

- Подключить домен, HTTPS, реальные изображения с разрешением на использование, юридическую информацию и политику конфиденциальности.
- Добавить восстановление пароля и подтверждение email, защиту от CSRF под выбранный домен, автоматические тесты, аудит действий админов, мониторинг, резервное копирование и полноценный платёжный workflow.
- Проверить одновременные заказы, финансовую отчётность, доставку email и нагрузку на реальной инфраструктуре.
- Для production: `cd frontend && npm run build` → разместите `frontend/dist` на web-сервере, а backend запустите в отдельном Node.js процессе через HTTPS reverse proxy.

## Важные ограничения текущего проекта

Это **исходный код функциональной демонстрации**, а не сертифицированный готовый коммерческий магазин. Не реализованы подтверждение email, сброс пароля, полноценная очередь писем, загрузка фотографий с диска через API (доступен URL изображений), реальные платежи, кассовые фискальные чеки и сложная аналитика. Для Windows/PDF используется англоязычный PDF-шаблон, чтобы избежать проблемы встроенных шрифтов PDFKit с кириллицей. Размеры US в Ring Size Finder лишь ориентировочные.
